每次随机初始化，不加载 PT 或 1115 checkpoint；最大 16 epoch，每半 epoch 验证，patience=4，仅保留最低 valid CE checkpoint。AdamW，学习率 3e-4 线性衰减，有效 batch=32（固定 16×2），BF16。BEAT/NOTE 合计每 512 事件直接切分，步长 512、无重叠，允许 NOTE 开头或拍内切分；每条演奏独立切分，尾块 padding 到 512。encoder/decoder 训练张量长度均为 512。decoder 历史 BEAT/NOTE 仍各以 0.5 概率整向量 mask，验证/生成不 mask。末尾不足两个 microbatch 的更新按实际数量归一化梯度和 loss，避免 1115 的 epoch 边界减半。

每项仅训练一次；普通配置 seed=42，D3/D5 延续独立复验用途使用 seed=45，但每项仍只有一次训练。最佳模型做三轮采样（temperature=1、top-p=0.9）；所有测试指标按三轮采样报告 mean ± sample std，三位小数。这不是训练随机性的标准差；stop epoch、valid CE 与 valid 物理误差为单次训练数值。

D 组依赖只使用单次训练的 valid 贪心物理误差：beat duration log MAE、note duration log MAE、onset ratio MAE、velocity MAE/127 四项均值。缺少某类事件的尾窗不伪造该属性指标；跨含该类事件的窗口平均后再合成分数。test 不参与设置选择；checkpoint 仍按 valid CE 选择。

测试为 19 首作品、82 个参考演奏（以冻结审计为准）；其中两首 MS-score 沿用旧评估的 MUSICAL51 raw 标签兜底，其余使用 grouped-median 标签。HR 保留固定 human anchor，使用生成后按实际起音时间排序的 MIDI note-index W1；token JS / onset / duration 误差保留 score event 身份，二者不能视为同一个对齐协议。PP 报告原始 W1，不额外构造未校准的 PP HR。

测试也按每条演奏每 512 个总事件直接切分，尾部 padding；每窗重置 BOS/cache，允许 NOTE 开头。预测后先按原始事件顺序拼回完整作品，再累计 beat duration、重建 note 起音；不会把 NOTE-first 窗口误当成一个新 beat。AR 任务按 batch=16 解码，保留三轮原始 token NPZ、MIDI 和逐作品指标。

## 6. 本轮设置与依赖

### 6.1 固定切分与 beat embedding

BEAT 与 NOTE 合计 512 个事件直接截断，步长 512、无重叠；允许在拍内切开，窗口可由 NOTE 开头。不追加 beat 锚点或额外上下文，不拼接不同演奏；每条演奏的尾块 padding 到 512，padding 不计入标签或 attention。NOTE onset 的比例定义仍相对于原 score beat，不会因切块重新定义。decoder 每窗从 BOS 开始，预测拼回原作品后再重建完整 beat 时间线。

BEAT 的输入为

$$e_{BEAT}=E_{beat}[m]+E_{duration}[d].$$

有 measure_start 时 $m\in\{0,1\}$，beat embedding 有两个 token；无区分时 $m=0$，只有一个 token。不再叠加另一份 BEAT 类型向量，也不另设 measure_start embedding。encoder 与 decoder 历史采用同样方式。NOTE 的其他编码和所有输出 head 沿用 1115；当前 score 位置的事件类型已知。

### 6.2 A/B/D 队列

abs 表示 duration 的自然对数（毫秒）绝对值，[3,8]、500 token；dev 表示 log(perf/score)，[-2,3]、500 token。onset 为 [-0.25,1]、500 token。encoder 和历史 duration 输入仍为 absolute-log。

### 6.3 与 1115 的可比范围

原始演奏事件、beat 映射、划分、连续标签、量化范围和 HR human anchor 均沿用冻结数据。更改为 512 总事件、任意边界、无重叠、16×2，以及单一 beat embedding，并修正 Trainer 末尾部分梯度累积。这是整体协议重跑，不是只有 batch 的单因素实验。由于旧训练约 50% 窗口重叠，每 epoch 的样本/事件曝光量也不同；不能只用 epoch 个数比较训练量。

固定长度仍需给每条演奏的尾块 padding；它不会保证每个位置都有真实事件。数据审计记录了尾部比例、NOTE-first 窗口和完整事件覆盖。新结果独立写于本文件，不覆盖 1115。

### 6.4 数据与自动记录

[固定切分审计](exp1116_BEAT_data_audit.json)。train/valid/test 均完整覆盖每条演奏的事件一次，分别为 6,561 / 329 / 974 个窗口；padding 占比约为 6.100% / 5.253% / 3.681%。三个 split 的作品完全分离，test 仍为 19 首、82 个演奏。

### 6.5 batch 与显存核对

已从 GPU0/1/2 三个运行中训练进程的命令行及各自 run_config 核对：microbatch=16、gradient accumulation=2、固定长度=512，三个任务分别独占一张卡。正常 batch 为 16 条窗口；训练集 6,561 条不能整除 16，最后一个 microbatch 只有一条。每个常规 optimizer update 累积 32 条窗口的梯度，并非同时保留 32 条窗口的激活。

2026-11-16 10:58 左右 nvidia-smi 显示每卡约 10 GiB、利用率约 78%–100%。这与 16×2 不矛盾：序列已缩为固定 512；参数、梯度和优化器状态不会随 microbatch 翻倍，activation 才随 batch 和长度变化。此前完整模型 16×2、长度 816 的独立检查峰值 reserved 也为 13.852 GiB，不能按“batch 16 必须约 20 GiB”判断是否生效。

### 7.2 输入表是否可以随意共享

不能说“无所谓”。在相同 seed=42、相同 abs target、相同 separate head 下，A1 与 B1 的唯一差别是 duration 输入表：B1 的 valid 物理分数从 0.201 降至 0.196，TF HR 从 1.984 降至 1.947，AR HR 从 3.720 降至 3.168；IOI HR、duration HR 也都下降。这是目前对 separate input tables 最直接的正向证据。

但每个配置只有一次训练，三次 sampling 的 `±` 只描述采样波动，不能描述训练 seed 波动。因此应把 B1 记为**当前最佳候选**，而不是已经证明 separate 表在统计上显著优于 shared 表。若要压缩参数，A1 是合理的近似基线；若优先当前指标，默认应保留 B1 的 separate duration input tables。

### 7.3 measure_start 是否可以去掉

证据是混合的，不能写成无所谓。A1 与 A3 使用相同 seed 和其他设置，去掉 measure_start 后 AR HR 反而从 3.720 降到 3.300，但 valid 分数略差（0.201 对 0.203）、TF HR 也略差（1.984 对 2.032）。D5 是 B1 的无 measure_start 变体，但它使用 seed=45；D5 AR=3.332 与 B1=3.168 的差异混合了 measure_start 和训练随机性，不能作为干净消融。

因此当前建议是：`measure_start` 对 valid/TF 的作用很小，AR 可能有收益也可能只是 seed 波动；在没有配对多 seed 复验前保留它，因为它只增加两个 beat embedding token，参数成本极小。若目标是最简模型，可以去掉，但应标记为未确定的设计选择，而不是已证明等价。

### 7.4 duration head 的结论

`separate` 是最明确的结论。D4 只把 D3 继承的 target 改成 separate input + shared-conditioned output head，valid 分数为 0.286、TF HR 为 2.453、AR HR 为 7.831；duration AR HR 为 12.820，远高于 B1 的 2.692。共享 output head 会把 BEAT duration 与 NOTE duration 的条件分布压到同一个输出映射，当前数据下明显造成 duration rollout 失稳。

### 7.5 当前推荐配置

在现有证据下，推荐默认配置为：

`absolute_log`（beat/note） + `separate duration input tables` + `separate duration output heads` + `measure_start` 保留。

这正是 B1 的配置。需要强调的是，B1 的“最佳”来自一次训练和三次 sampling；正式宣称输入表或 measure_start 的稳定收益，还需要至少两个以上训练 seed 的配对复验。当前文档中的排序适合决定下一轮默认设置，不适合当作最终统计结论。
